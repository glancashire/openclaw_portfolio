# Phase 213 Plan — HTML Email Readability Refresh

## Objectives
- Improve readability of all HTML email/report surfaces generated by the shared email rendering helpers.
- Remove redundant framing text and repeated status phrasing so emails feel tighter and easier to scan.
- Make the layouts more mobile friendly with cleaner spacing, better stacking, and narrower cognitive load on small screens.
- Move the visual style toward a modern light, colorful design while preserving email-client safety and stronger contrast.
- Eliminate low-contrast text/background combinations, especially in muted, warning, and hero callout areas.

## Scope
Primary shared/rendered surfaces to refresh:
- `src/reporting/emailHtml.js`
- `src/reporting/reportEmail.js`
- `src/reporting/healthReport.js`
- `src/reporting/dashboardDigest.js`
- any related HTML output tests/snapshots that encode current structure or wording

## Risks / Dependencies
- HTML emails must stay robust in constrained email clients; avoid over-reliance on unsupported CSS.
- Existing tests may assert exact wording/HTML fragments and will need careful updates.
- Tightening copy must not remove important operator guidance or risk posture cues.
- Shared helper changes can affect multiple email types at once, so verification must cover all affected paths.

## Readability / Design Targets
- Stronger visual hierarchy:
  - cleaner hero/header
  - fewer badges competing for attention
  - more obvious primary next-action panel
- Tighter copy:
  - trim repeated “currently surfaced” / “pending item(s)” style filler
  - reduce duplicate restatement across summary, priorities, and status tables
- Better mobile behavior:
  - reduce oversized paddings on narrow screens
  - ensure metric blocks and tables collapse gracefully
  - prefer short cards over huge dense sections
- Better contrast:
  - darker muted text on light backgrounds
  - stronger warning/danger text against tinted panels
  - avoid pale gray-on-gray combinations
- More modern light style:
  - brighter accent palette
  - softer surfaces/cards with clear separation
  - colorful but restrained status chips and hero accents

## Actionable Checklist
- Review current helper palette, spacing, table, badge, and card patterns in `emailHtml.js`.
- Introduce safer modern light color tokens with improved contrast.
- Add basic mobile-friendly structural adjustments that remain email-client safe.
- Simplify shared components where possible (cards, badges, metric grid, tables, bullet lists).
- Tighten report email copy structure:
  - management summary
  - immediate priorities
  - status block
  - supporting detail
- Tighten health email copy structure and remove duplicated state narration.
- Tighten digest email sections and reduce repeated next-step/workflow phrasing.
- Update/add focused tests for HTML rendering and major section presence.
- Regenerate/verify affected HTML outputs.
- Run focused tests, then full `npm test`.

## Acceptance Criteria
- Email HTML uses a higher-contrast modern light design.
- Mobile readability is improved without breaking email-client compatibility.
- Redundant text is materially reduced across report, health, and digest emails.
- All affected tests pass, and the full suite remains green.
- Final source + generated/report artifacts are tidied and committed cleanly.
