# Test lanes

OpenClaw's portfolio-manager test suite is split into four lanes so that the
fast, always-green pre-commit gate stays separate from broader regression
sweeps and from tests that touch external services.

## Layout

| Lane | What it covers | When it runs |
|---|---|---|
| **safe** | Pure unit tests. No filesystem fixtures, no network, no broker, no Mailgun. | `npm run test:all -- --lane=safe`, periodic / CI sweeps. |
| **integration** | Needs portfolio fixtures or runtime artifacts but no network. | `npm run test:all` (default = safe + integration), periodic. |
| **live-smoke** | Connects to the IBKR gateway or the open internet. | Manual: `npm run test:all -- --lane=live-smoke` only when IBKR is up. |
| **external** | Calls Mailgun / external paid APIs. | Manual, in dedicated integration sessions. |

## Curated gate vs broad sweep

- **`npm test`** runs `scripts/verify-repo.js`, which executes the curated
  list in `src/reporting/verifyRepoChecks.js` (~49 hand-picked tests). This
  is the **always-green pre-commit gate**.
- **`npm run test:all`** (= `scripts/run-all-discovered-tests.js`) reads
  `docs/operations/test-manifest.json` and runs the **safe + integration**
  lanes by default. Use this for periodic full-repo validation.
- **`npm run test:all -- --lane=safe`** is the cheap, broad,
  network-free sweep — safe to run anywhere.
- **`npm run test:all -- --lane=live-smoke`** is opt-in; expect it to fail
  unless you have IBKR Gateway up on `127.0.0.1:4001` (see `TOOLS.md`).
- **`npm run test:all -- --lane=external`** is opt-in and **will send real
  Mailgun emails**. Only run with a recipient you control.

## Manifest

`docs/operations/test-manifest.json` is the single source of truth. It is
generated by `scripts/discover-test-suites.js` and validated by
`scripts/test-test-manifest-shape.js` (wired into the curated gate as
`test:test-manifest-shape`).

Each entry has:

- `path` — repo-relative file path
- `lane` — one of `safe | integration | live-smoke | external`
- `reason` — why the discoverer chose that lane
- `inVerifyRepoChecks` — whether the curated gate already runs it
- `quarantined` — `true` to skip in `test:all` (with `quarantineReason`)

## Adding a new test

1. Drop the file under `scripts/test-*.js` or `tests/test-*.js`.
2. If it's a normal unit / integration test, no extra config is needed.
3. If it talks to a broker or sends email, ensure the discoverer picks the
   right lane:
   - `lib/mailgun` import or `node-fetch` ⇒ `external`
   - imports `brokers/interactive-brokers/client` (or `nativeClient`) **and**
     calls `.authenticate(` / `.connect(` ⇒ `live-smoke`
   - Otherwise add an explicit override in `OVERRIDES` inside
     `scripts/discover-test-suites.js`.
4. Regenerate the manifest:
   ```bash
   node scripts/discover-test-suites.js
   ```
5. Commit the test file **and** the regenerated manifest.
6. (Optional) If the test belongs in the always-green gate, add it to
   `src/reporting/verifyRepoChecks.js`. The discoverer will flip its
   `inVerifyRepoChecks` to `true` on the next run.

## Quarantining a flaky / known-broken test

Edit the `QUARANTINE` map at the bottom of
`scripts/discover-test-suites.js`:

```js
const QUARANTINE = {
  'scripts/test-foo.js': 'pre-existing failure tracked in #123',
};
```

Regenerate the manifest. The runner will skip quarantined tests with a
visible `SKIP (quarantined)` line. Quarantine is for tests already in
`test:all`; do not quarantine curated gate tests — fix or remove them.

## Drift detection

The curated gate runs `scripts/test-test-manifest-shape.js`, which fails
with a clear message if:

- the manifest is missing or malformed
- any test file on disk isn't represented
- the manifest references a file that no longer exists
- a curated check isn't marked `inVerifyRepoChecks: true`
- entries aren't sorted by path

Re-running `node scripts/discover-test-suites.js` resolves all of those.

For a stale-manifest check without rewriting:

```bash
node scripts/discover-test-suites.js --check
```

(Exits non-zero if the on-disk manifest doesn't match what the discoverer
would produce.)
